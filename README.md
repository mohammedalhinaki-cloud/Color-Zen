# Color Zen

A calm, minimal **water-sort puzzle** for Android, built with Jetpack Compose
and ready for Google Play publishing. No ads. No music. No data collection.

## The game

* Tap a bottle to lift it, tap another to pour. Liquid pours only onto the same
  colour or into an empty bottle, and the whole matching run moves (or as much
  as fits).
* **120 levels** in six difficulty tiers, from 4 bottles / 3 colours up to
  13 bottles / 11 colours. Every level is machine-proven solvable.
* Levels 1-30 free; then three packs of 30 levels, or the Full Game.
* Undo, shuffle, restart and hints (hints reveal the solver's best next pour).
* Stars per level based on moves vs. the pre-computed par.
* Colour themes and bottle designs as a one-time themes purchase.
* English + Arabic with full RTL mirroring; sound effects only, mutable.

## Monetisation (Google Play Billing 9)

| Product | Type | Effect |
|---|---|---|
| `level_pack_1/2/3` | non-consumable | levels 31-60 / 61-90 / 91-120 |
| `full_game` | non-consumable | all 120 levels |
| `color_themes` | non-consumable | 4 palettes + 3 bottle designs |
| `hint_pack_10` | consumable | +10 hints |

Prices are **never hard-coded**: the shop renders `formattedPrice` from Play at
runtime. No subscriptions, no ads.

## Architecture

Single-activity Compose app, `minSdk 23` / `targetSdk 36`, AAB output.

```
app/src/main/java/com/colorzen/puzzle/
├── core/        AppConfig, Entitlements (pure unlock rules), PlayerStore
│                (SharedPreferences + StateFlow), SoundManager, AppContainer
├── game/        GameRules, Solver (DFS hints), BoardGeometry (pure grid math),
│                LevelPlan, LevelRepository (levels.json), Palettes
├── billing/     ProductIds/Catalogue, BillingManager (purchase + restore)
├── ui/          theme, nav, components, game (board canvas + pour animation),
│                levels, shop, settings, privacy, menu
└── MainActivity.kt
```

Design rules worth knowing:

* **Pure core**: `GameRules`, `Solver`, `BoardGeometry`, `Entitlements` and
  `LevelPlan` have no Android dependencies and are covered by JVM unit tests
  (`app/src/test/`).
* **No icon library**: every drawable is generated by `tools/generate_icons.py`
  (vector XML + launcher PNGs), verified visually via a contact sheet.
* **No music**: six synthesised SFX in `res/raw/` from `tools/generate_sfx.py`.
* **Reactivity**: screens read `ownedProducts` / `results` through
  `collectAsState()` and then call `Entitlements`, so a purchase unlocks the
  level grid immediately.
* **Pour animation** runs in the composable layer (`Animatable`), with the
  ViewModel applying the move on animation completion - ViewModels never
  animate.

## Repository tools

| Script | Purpose |
|---|---|
| `tools/generate_levels.py` | builds `assets/levels.json` (120 levels × 3 solver-verified variants) + diagnostics |
| `tools/generate_icons.py` | all vector drawables, launcher icon vectors + legacy PNGs, contact sheet |
| `tools/generate_sfx.py` | the six WAV sound effects |
| `tools/generate_assets.py` | Play icon, feature graphic, marketing screenshots |
| `tools/check_listing.py` | validates store copy against Play character limits |

Generated previews land in `tools/preview/` (git-ignored).

## Build

Requires JDK 17 and Android SDK 36.

```bash
./gradlew testDebugUnitTest   # JVM tests
./gradlew assembleDebug       # debug APK
./gradlew bundleRelease       # Play bundle (AAB)
```

Signing: copy `keystore.properties.example` to `keystore.properties`
(git-ignored). Without it, release builds fall back to the debug key so CI
stays green.

## Privacy stance

No `INTERNET` permission, no analytics, no ads, no accounts. The only declared
permission is `com.android.vending.BILLING`. Player progress lives in the app's
private SharedPreferences and leaves the device only through the user's own
Android backup, if they enabled it.
